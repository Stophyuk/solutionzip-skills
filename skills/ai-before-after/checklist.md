# 전후 비교 점검표

위에서부터 본다. 스크립트가 잡는 것은 ⚙, 사람이 보는 것은 👀.

## 시작 전

- 👀 바꾸는 것 한 줄, 잴 것 한 줄(좋아져야 할 것 하나 · 나빠지면 안 되는 것 하나)을 사용자가 봤다
- 👀 정답 라벨이 있는지 확인했다. 없으면 "정확도는 재지 않는다"를 먼저 말했다
- 👀 설명 · 요약 · 초안처럼 정답이 하나가 아닌 일은 정확도 대신 읽기로 본다. 읽을 표본 몇 건을 미리 정해 두고, 전 · 후 같은 건을 읽는다

## 표본

- 👀 20~50건. 적을수록 한 건의 무게가 크다(표가 "한 건이 몇 %p"를 알려 준다)
- 👀 최근 것만 고르지 않는다. 기간을 나눠 고르고, 종류(라벨)마다 몇 건씩
- 👀 끝을 넣는다: 아주 짧은 것 · 아주 긴 것 · 빈 입력 · 다른 언어 · 이모지 · 표나 목록 · 모델에게 시키는 말이 섞인 글
- 👀 지금 틀리는 것으로 알려진 것, 두 종류 사이에 걸친 애매한 것을 넣는다. 고친 이유가 된 건은 꼭
- 👀 개인정보를 가렸다: 이름 · 전화 · 메일 · 주소 · 계좌 · 주문번호 → `<이름>` · `<전화>`. 문장 꼴은 남긴다
- 👀 표본 파일은 커밋하지 않는다
- 👀 전 · 후 사이에 표본을 고치지 않는다. 고쳐야 하면 전부터 다시 뜬다
- ⚙ id가 겹치거나 JSON이 아닌 줄이 있으면 run.mjs가 멈춘다
- ⚙ 표본이 달라지면(해시가 다르면) compare.mjs가 `주의:`를 찍는다

## 어댑터

앱이 쓰는 함수를 그대로 부른다. 프롬프트를 어댑터에 따로 베껴 조립하지 않는다(베낀 것은 낡는다).

```js
// predict.mjs — calls the app's own function; the paid model only when REAL=1
import { classify } from "../src/lib/classify.js";

const fake = async () => '{"label":"other","reply":"시험 답"}'; // fixed answer, costs nothing

export async function predict(input, ctx) {
  const r = await classify(input, ctx.real ? {} : { callModel: fake });
  if (r.usage) ctx.usage({ in: r.usage.input, out: r.usage.output });
  return r.result;
}
```

- 👀 가짜 모델을 끼울 자리가 앱에 없으면 `predict` 첫 줄에서 막는다: `if (!ctx.real) throw new Error("REAL=1 없이 실제 모델을 부르지 않는다")`. 0원 단계는 `--mock`으로 한다
- 👀 어댑터가 DB에 쓰지 않는다 · 메일 · 알림을 보내지 않는다 · 사용량 기록이나 한도를 건드리지 않는다. 서버 액션 · API 경로보다 그 안의 함수를 직접 부른다
- 👀 서버 전용 모듈이 밖에서 불러오면 오류를 내면, 그 함수만 따로 떼어 부른다
- 👀 키는 앱이 읽는 곳에서 읽게 두고, 어댑터에서 찍지 않는다

## 돌리기

- ⚙ `--concurrency`(동시에 몇 건, 기본 4) · `--retries`(기본 2) · `--timeout`(ms, 기본 60000) · `--limit N` · `--dry`
- ⚙ 끝난 건은 바로 파일에 붙는다. 중간에 죽어도 끝난 건은 남는다
- ⚙ 결과 파일이 이미 있으면 멈춘다. '후'를 '전' 이름으로 떠서 기준선을 지우는 일을 막는다(`--force`로만 덮어쓴다)
- ⚙ 시간 초과는 실패로 적지만 늦은 호출을 취소하지는 못한다. 유료 호출은 끝까지 돌아 과금될 수 있다
- 👀 실제 모델이면 비용 어림을 먼저 말했다. 재시도까지 치면 최대 건수 × (1 + retries)번이다(run.mjs가 찍는다)
- 👀 모델 설정(온도 · 최대 토큰 · 생각 설정)을 전 · 후 같게 뒀다
- 👀 흔들림을 쟀다: 같은 코드로 두 번 떠서 달라진 건수. 후의 차이가 이보다 크지 않으면 "모름"
- 👀 날을 넘겨 견줄 때는 전도 그날 다시 뜬다. 제공자 쪽 모델이 바뀌었을 수 있다

## 표 읽기

- ⚙ 실패(에러): 예외 · 시간 초과. 늘었으면 이것부터 본다
- ⚙ 빈 출력: null · 빈 문자열 · 빈 칸만 있는 객체
- ⚙ 형식 위반: `--schema`를 줄 때만. 문자열 출력은 JSON으로 읽어 본 뒤 검사한다(```json 울타리는 벗긴다)
- ⚙ 길이: `--text` 칸의 글자 수. 없으면 라벨 칸을 뺀 모든 글자. 빈 출력은 뺀다
- ⚙ 라벨 분포: `--pred` 칸. 한쪽으로 쏠림 · '기타'로 빠짐 · 스키마 밖 새 라벨을 본다
- ⚙ 달라진 표본 · 라벨이 바뀐 건 · 새로 맞은 건 · 새로 틀린 건: id 목록. `--show`로 읽을 건을 여기서 고른다
- ⚙ 입력에 없는 숫자: 출력의 숫자 중 입력에 없는 것. 쉼표는 무시하고 줄 머리의 "1." 같은 번호는 뺀다. 한글로 쓴 수("세 개")는 못 잡는다
- ⚙ 입력에 없는 영문 낱말: 고유명사 · 링크 의심. 한글 고유명사는 못 잡는다 — 읽어서 본다. 번역 · 영문 출력이면 이 줄은 뜻이 없다
- ⚙ 금칙어: `--ban` 파일, 한 줄에 정규식 하나(대소문자 무시, `#`은 주석)
- ⚙ 정확도: 라벨 있는 건만. 실패는 틀린 것으로 센다. 대소문자 · 앞뒤 공백은 무시한다
- ⚙ 라벨이 하나도 없으면 정확도 칸에 "라벨 없음 — 정확도는 재지 않았다"

## 판정 · 보고

- 👀 좋아진 것: 1의 기준이 움직였고, 나빠지면 안 되는 것은 그대로다
- 👀 나빠진 것: 새로 틀린 건 · 새 실패 · 새 형식 위반 · 새로 나온 숫자. 좋아진 것과 같이 말한다
- 👀 모르는 것: 흔들림보다 작은 차이 · 라벨 없이는 못 재는 것(뜻이 맞나) · 읽지 않은 건
- 👀 "좋아졌다"에는 표의 줄과 읽은 id가 같이 붙어 있다
- 👀 출력 본문은 `--show`로 고른 몇 건만. 결과 파일 경로를 남긴다
