# AI 티 점검 스킬

AI 티는 색이 아니라 절제의 부재다. 보라 · 다크 · 네온은 그 자체로 문제가 아니고, 표면 효과가 한 화면에 세 겹 이상 겹칠 때 티가 난다. 레퍼런스 스크린숏 11,918장을 재서 얻은 결론이다(`findings.md`). 그래서 이 스킬은 색을 탓하지 않고 겹침을 센다.

## 순서

1. **대상 받기.** URL이나 HTML 파일 경로를 받는다. 없으면 묻는다.
   - 로그인 뒤 화면이면 로그인 없이 열리는 주소(미리보기 · 로컬 개발 서버)를 달라고 한다.
   - 로컬 개발 서버면 켜져 있는지 먼저 본다.
2. **재기.** `node <이 폴더>/check.mjs <URL 또는 파일> anti-slop-out`
   - PC 1366×768 · 폰 390×844 두 폭으로 열고, 끝까지 한 번 내렸다 올라와서 잰다(늦게 뜨는 블록까지 보려고).
   - 나오는 것: `report.json`, 첫 화면 `pc.png` · `phone.png`, 전체 `pc-full.jpg` · `phone-full.jpg`.
   - exit 2(못 엶)면 이유를 말하고 멈춘다. exit 1은 고칠 것이 있다는 뜻이지 실패가 아니다.
3. **눈으로 보기.** 스크린숏 넷을 Read로 직접 연다. `checklist.md`를 위에서부터 보되, (눈) 항목을 꼭 본다 — 아이콘이 정보를 더하나, 가짜 후기 · 숫자, AI 스톡 사진, 제목과 본문의 크기 차이.
   - 쿠키 배너 · 팝업이 첫 화면을 덮었으면 픽셀 축은 그것을 잰 것이다. 보고에 적는다.
   - 점검기 지적이 오탐이면 버리고 이유를 한 줄 적는다(예: 헤더의 상시 버튼, 의도한 코드 글꼴). 규칙이 화면보다 거칠면 지적을 믿을 수 없다.
4. **보고.** 아래 순서로, 짧게.
   1. 겹침 — fire n/5와 켜진 축, 장식 3겹 상자(어디 · 무엇이 겹쳤나), 화면을 덮는 그라디언트 · 네온 · 그라디언트 글자
   2. 상투 문구 — 걸린 말과 자리
   3. 구성 · 움직임 — 카드 안 카드, 첫 화면 채움 버튼, 글꼴, 이모지 · 아이콘 타일, 여백, 바운스 · 끝없는 반복
   4. 접근성 — 덤으로 한 줄씩(대비 · 작은 글자 · 터치 · 포커스)
   - 판정 말은 "겹침 낮음 · 후보 · 강함"만 쓴다. "AI가 만들었다/안 만들었다"고 말하지 않는다.
5. **고칠 것 세 개.** 우선순위대로 셋만 고른다 — 겹침 → 문구 → 나머지. 각각 "지금 → 대신" 한 줄과 자리(선택자).
   - 사용자가 고치자고 하면 그때 고친다. 고친 뒤 check.mjs를 다시 돌려 전후 숫자(fire, 중요 · 보통 수)를 나란히 보여 준다.

## check.mjs가 보는 것

| 묶음 | 무엇 | 걸리는 선 |
|---|---|---|
| 픽셀(첫 화면) | 축 다섯: ramp(전면 그라디언트) · hue_travel(색상환 회전) · sat_share(채도 높은 면적) · hue_n(강조색 수) · glow(가운데 후광) + 게이트 cdetail(매끈한 색 면인가) | 켜진 축 수 fire ≥ 3 후보, ≥ 4 강함 |
| 겹침 | 화면 30% 이상 덮는 그라디언트 · 한 상자에 장식 3겹 · 네온 글로우 · 그라디언트 글자 · 그라디언트 면 4개 이상 | 앞의 둘은 중요 |
| 문구 | 상투 문구(`phrases.md`) · 본문 문장 안 긴 대시 | 상투 문구 4종 이상이면 중요 |
| 구성 | 카드 안 카드 · 첫 화면 채움 버튼 2개 이상 · 글꼴 3벌 · 4의 배수 아닌 여백 10% 이상 · 이모지 라벨 · 아이콘 타일 줄 | 앞의 둘은 중요 |
| 움직임 | 역할별 길이 상한 · 바운스 이징 · 끝없이 도는 장식 | 바운스는 중요 |
| 접근성 | 대비 4.5:1 · 13px · 폰 터치 44px · Tab 포커스가 보이나 | 대비는 중요 |

## 지킬 것

- 색을 탓하지 않는다. 보라 · 다크 · 네온 · 그라디언트는 하나만 있으면 문제가 아니다. 문제는 겹침이다.
- 팔레트를 새로 짜 주지 않는다. 브랜드 색은 두고, 겹친 것 중 하나만 남기는 쪽으로 제안한다.
- 이 점검은 "AI가 만들었나"를 맞히지 못한다. 하나의 실패 꼴(전면 그라디언트 + 여러 색 + 매끈한 색 면 + 장식 겹침)을 잡는다.
- 시안을 넓게 탐색하는 단계에는 쓰지 않는다. 방향을 고른 뒤 화면을 다듬을 때 쓴다.
- 금지 목록만 지키면 특징 없는 화면이 나온다. 뺀 자리는 글자 크기 대비와 여백으로 채운다.
- 남의 사이트는 재고 보고만 한다. 찍은 화면은 내 컴퓨터에서 보는 데만 쓰고 어디에 올리지 않는다.
- 문구를 고칠 때 확인 안 된 숫자 · 최상급 · 보장을 새로 넣지 않는다. 가짜 후기 · 로고 · 숫자는 빼는 쪽으로 제안한다.

## 필요한 것

- Node 18 이상, 작업 폴더나 그 위에서 `npm i playwright` 한 번. 설치된 크롬을 먼저 쓰고, 없으면 `npx playwright install chromium`.
- 같은 폴더의 참고 파일: `checklist.md`(10항 — AI 티 꼴 · 대신 이렇게), `phrases.md`(상투 문구와 대신 쓸 말), `findings.md`(이 기준이 어디서 나왔나 · 한계).
