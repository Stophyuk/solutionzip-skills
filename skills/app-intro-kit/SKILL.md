# 앱 소개 스킬

만든 앱을 문제해결집 '바이브코딩 월드컵'에 올릴 때 쓴다. 먼저 **출품 양식**을 뽑는다 — 프로젝트를 읽어 아홉 칸을 채우고, 글자 수를 세고, 화면 한 장과 로고를 챙긴다. 더 보여 줄 것이 있으면 그 뒤에 **소개 자료**(슬라이드 HTML · PDF · 영상)를 만든다. 소개 자료는 선택이다.

## 출품 양식

대결 화면에는 로고 · 컨셉 한 줄 · 누구의 어떤 문제 · 어떻게 푸나 · 화면 한 장만 보인다. 앱 이름 · 주소 · 만든 사람 · 긴 소개는 로그인한 회원에게만 열린다. 이름이 아니라 누구의 어떤 문제를 어떻게 푸는가로 고르는 판이라, **대결에 보이는 세 줄에는 앱 이름을 쓰지 않는다.**

등록 화면에 아래 꼴을 붙여 넣으면 칸이 채워진다. 줄마다 `키: 값`이고, 키는 글자 그대로 쓴다.

```
[바이브코딩 월드컵 출품 양식]
앱 이름: …
컨셉 한 줄: …            (6~22자 · 앱 이름을 넣지 않는다)
누구의 어떤 문제: …        (8~28자)
어떻게 푸나: …            (8~28자)
들어가 볼 주소: https://…   (실제로 들어가 볼 수 있는 주소나 스토어 링크)
만든 사람: …              (30자 안 · 비우면 계정의 표시 이름)
만든 도구: …              (40자 안)
만든 기간: …              (20자 안)
긴 소개: …               (300자 안)
```

괄호는 설명이다. 출력에는 넣지 않는다. 로고와 화면 그림은 양식에 없다 — 등록 화면에서 파일로 올린다.

## 순서 — 출품 양식

1. **프로젝트 읽기.** 묻기 전에 읽는다. README · `package.json`(name · description · author · homepage · 의존성) · 라우트(`app/` · `pages/` · `src/routes` 등) · 첫 화면과 핵심 기능 화면의 코드 · 배포 설정 · `git log`의 첫 커밋과 마지막 커밋 날짜.
2. **칸 채우기.** 읽은 데 근거가 있는 칸만 채운다. **모르는 칸은 비워 두고, 지어 채우지 않는다.**
   - 앱 이름(30자 안): README 제목 · manifest의 `name` · `<title>`. 쓰인 이름 그대로.
   - 컨셉 한 줄(6~22자): 처음 보는 사람이 한 번에 알아듣는 한 줄. 기능 나열 · 최상급 없이.
   - 누구의 어떤 문제(8~28자): **"~하는 사람"으로 끝낸다.** 직업 이름보다 그 사람이 겪는 상황으로. 예: "가게 블로그에 뭘 쓸지 몰라 비워 둔 사람".
   - 어떻게 푸나(8~28자): 쓰는 사람이 무엇을 하면 무엇이 되는지 적고 **"~합니다"로 끝낸다.** 예: "몇 줄 적으면 제목과 본문을 써 편집기에 넣습니다".
   - 문제와 해결의 끝말은 월드컵 등록 화면의 프롬프트와 같다. 대결에서 두 카드가 나란히 서니 꼴이 같아야 읽기 쉽다.
   - **위 세 줄에는 앱 이름 · 서비스 주소 · 만든 사람 이름을 넣지 않는다.** 앱 이름은 한글 · 영문 표기, 도메인에 든 이름까지. 주소 · `www.` · 도메인 · 메일 꼴이 들어 있으면 등록 화면이 그 칸을 받지 않는다.
   - 들어가 볼 주소: 배포된 주소나 스토어 링크. `localhost` · 미리보기 주소 · 저장소 주소는 안 된다. README · `homepage` · 배포 설정에서 찾고, 없으면 묻는다. 실제로 들어가 볼 수 있어야 올릴 수 있다.
   - 만든 사람(30자 안): README · `package.json`의 author에 적혀 있을 때만 후보로 삼고, 이 이름으로 나가도 되는지 묻는다. 닉네임도 된다. `git config`의 이름과 메일은 쓰지 않는다. 후보가 없으면 비워 둔다 — 등록 화면이 로그인한 계정의 표시 이름으로 채운다.
   - 만든 도구(40자 안): 프로젝트에 흔적이 있는 것만 가운뎃점으로 나눈다 — `CLAUDE.md` · `.cursor/` · `AGENTS.md`, 의존성의 프레임워크. 예: "Next.js · Supabase · Claude Code".
   - 만든 기간(20자 안): 첫 커밋 날짜부터. "2주", "2026.08 ~"처럼. git 기록이 없으면 비운다.
   - 긴 소개(300자 안): 누가 언제 쓰는지, 핵심 기능 두세 가지, 지금 어디까지 됐는지를 문장으로. 줄을 바꾸지 않고 한 줄로 쓴다. 숫자 · 실적은 프로젝트에 근거가 있는 것만.
   - 어느 칸에도 키 · 비밀번호 · 내부 주소 · 다른 사람의 이름과 연락처를 적지 않는다.
3. **검사.** 작업 폴더(예: `app-intro/`)를 만들고 `sheet.txt`에 양식을 적은 뒤 `node <이 폴더>/sheet.mjs sheet.txt` — 칸별 글자 수, 넘친 칸, 빈 필수 칸, 주소 꼴, 세 줄에 든 앱 이름 · 만든 사람 · 주소 · 메일을 알려 주고, 통과하면 붙여 넣을 블록을 출력한다.
   - 글자 수는 눈대중으로 세지 않는다. 스크립트가 센 값을 쓴다(한글 한 글자가 1자).
   - **실패**가 있으면 고쳐서 다시 돌린다. 넘친 칸은 뜻을 지키며 줄인다. 말줄임(…)으로 자르지 않는다.
   - 필수 칸(앱 이름 · 컨셉 · 문제 · 해결 · 주소)이 비었으면 그 칸만 사용자에게 묻는다.
   - **경고**(문제 · 해결의 끝말 · 빈 만든 사람 · 숫자 · 확인하기 어려운 표현 · 주소에 든 이름 · 주소 종류(저장소 · 임시 터널 · IP) · 양식 밖의 줄)는 읽고 판단한다. 끝말 경고는 고쳐서 다시 돌린다.
   - 앱 이름의 다른 표기가 있으면 `--also "MyApp,마이앱"`으로 같이 검사한다.
4. **화면 한 장.** 작업 폴더에서 `node <이 폴더>/capture.mjs <주소> / /경로 …` — 경로마다 PC · 폰 첫 화면을 `shots/`에 찍는다. 그중 한 장을 고른다.
   - **앱 이름이 크게 보이지 않는 화면**을 고른다. 앱이 하는 일이 보이는 화면(쓰는 화면 · 결과 · 목록)이 좋고, 이름이 제목인 랜딩 첫 화면 · 로그인 · 시작 화면은 피한다.
   - 머리의 작은 로고는 괜찮다. 크면 `--hide "header .logo"`처럼 그 요소만 뺀다.
   - 찍은 PNG를 열어 직접 본다. 가장 큰 글자가 앱 이름이면 다른 화면으로 바꾼다.
   - 로그인 · 결제 · 제출은 하지 않는다. 핵심 화면이 로그인 뒤에 있으면 사용자에게 캡처를 받는다(시험용 계정으로). 이미 찍어 둔 실제 화면이 있으면 그것을 쓴다.
   - 다른 사람의 이름 · 메일 · 주문 내역 · 대화가 보이면 가리거나 시험용 데이터 화면으로 바꾼다.
5. **로고.** 프로젝트의 아이콘 파일을 찾아 경로를 알려 준다. 새로 그리지 않는다.
   - 웹: `app/icon.png` · `app/apple-icon.png`(`src/app/`도) · `public/apple-touch-icon.png` · `public/icon-512.png` · `public/logo.*` · `manifest.json`의 `icons`.
   - 앱 · 확장: Expo `assets/icon.png` · iOS `AppIcon.appiconset/` · Android `mipmap-xxxhdpi/ic_launcher.png` · 확장 `icons/`.
   - PNG · JPG · WebP 가운데 가장 큰 정사각형을 고른다. 이름을 글자로 쓴 워드마크와 심볼이 둘 다 있으면 심볼 쪽.
   - **SVG는 받지 않는다.** SVG · ICO뿐이면 PNG로 바꾼다 — 맥은 `sips -s format png -Z 512 icon.svg --out logo.png`, ImageMagick이 있으면 `magick -background none icon.svg -resize 512x512 logo.png`.
   - 아이콘 파일이 없으면 없다고 알린다.
6. **한 번에 보여 주기.** `sheet.mjs`가 출력한 블록을 그대로 붙이고, 그 아래에 그림 두 장의 경로와 비워 둔 칸 · 그 까닭을 적는다. 한 메시지로.

   ```
   로고: app-intro/logo.png (512×512 PNG)
   화면 한 장: app-intro/shots/write-pc.png
   비워 둔 칸: 만든 도구 — 프로젝트에서 근거를 찾지 못함
   ```

   - 올리기는 사용자가 한다. 월드컵 등록 화면에서 로그인하고, 블록을 붙여 넣고, 그림 두 장을 올린다. 큰 그림은 등록 화면이 줄여서 올린다(로고 512px · 화면 긴 변 1280px).

## 순서 — 소개 자료 (선택)

양식과 그림 두 장이면 올릴 수 있다. 소개 자료는 앱 상세에서 로그인한 회원이 보는 것이라, 더 보여 줄 것이 있을 때만 만든다.

앱 소개를 HTML 한 장에 슬라이드로 짜고, 헤드리스 크롬으로 PDF와 영상까지 뽑는다. 결과 HTML은 글꼴과 그림이 전부 파일 안에 들어 있어서, 바깥 요청을 막은 뷰어(sandbox iframe · CSP)에서도 그대로 열린다. 월드컵의 소개 자료 칸(PDF 20MB 이하 · HTML 한 파일 5MB 이하 · 영상은 유튜브 주소)에 맞춰 두었다.

1. **재료 받기.** 아래 일곱 칸을 한 메시지로 묻는다. 출품 양식을 먼저 뽑았으면 그 값을 가져오고 빈 칸만 묻는다. 모르는 칸은 비워 두고, 지어 채우지 않는다.
   - 앱 이름 · 한 줄(누구에게 무엇이 생기나)
   - 누구의 무슨 문제 — 그 문제가 보이는 장면 하나
   - 어떻게 푸나 — 사용자가 하는 일 세 단계
   - 화면 — 캡처 파일이 든 폴더, 또는 앱 주소(로그인 없이 보이는 화면만 찍는다)
   - 만든 사람 — 이름 또는 닉네임 · 맡은 일 · 만든 도구
   - 써 본 결과 — **잰 숫자와 어디서 잰 값인지.** 없으면 "없음"
   - 다음 — 지금 고치는 것 · 다음에 붙일 것
2. **장표 먼저.** 장마다 한 줄씩(장 · 제목 · 한 줄 · 그림) 표로 보여 주고 답을 받는다. 6~10장.
   - 기본 순서: 표지 → 문제 → 누구 → 어떻게(화면 1~3장) → 써 본 결과(있을 때만) → 다음 → 만든 사람.
   - 한 장에 한 메시지. 문장은 짧게 — 뷰어는 슬라이드를 페이지 안의 틀에 맞춰 줄여 띄우고, 폰에서는 더 작다.
3. **화면 캡처.** 파일이 없으면 `node <이 폴더>/capture.mjs <주소> / /경로 …` — 경로마다 PC(1440×900) · 폰(390×844) 첫 화면을 `shots/`에 찍는다.
   - 긴 페이지 전체가 필요하면 `--full`, 쿠키 띠 · 채팅 버튼은 `--hide ".선택자"`로 뺀다.
   - 로그인 · 결제 · 제출은 하지 않는다. 핵심 기능이 로그인 뒤에 있으면 사용자에게 직접 캡처 · 녹화를 받는다(시험용 계정으로).
   - 캡처에 다른 사람의 이름 · 메일 · 주문 내역 · 대화가 보이면 가리거나 시험용 데이터 화면으로 바꾼다.
4. **HTML 쓰기.** 작업 폴더(예: `app-intro/`)에 이 폴더의 `template.html`을 `deck.html`로 복사해 고친다.
   - 슬라이드 하나 = `<section class="slide 꼴" data-slide="이름">`. 꼴은 `cover`(표지) · `statement`(문제 한 문장) · `who`(누구) · `how`(단계 + 화면) · `screen`(넓은 그림 한 장) · `result`(써 본 결과) · `next`(다음) · `maker`(만든 사람). 안 쓰는 장은 지우고, 화면 장은 늘려도 된다.
   - 색은 맨 위 `:root`만 바꾼다 — `--app`(바닥글의 앱 이름) · `--accent`(앱의 대표색) · `--accent-soft`(옅은 대표색).
   - 그림은 작업 폴더 안 파일을 `<img src="./shots/home-pc.png">`로. PC 화면은 `frame pc`, 폰 화면은 `frame phone`, 그림 그대로는 `frame free`.
   - 글꼴은 `node <이 폴더>/build.mjs --fonts`로 Pretendard를 `./fonts`에 한 번 받는다(SIL OFL — 문서에 넣어 배포해도 된다).
   - **CDN · 웹 글꼴 주소 · `<link rel="stylesheet">` · 바깥 그림 주소를 쓰지 않는다.** 월드컵 뷰어는 바깥 요청을 전부 막는다.
   - 주소는 `<a>` 링크 대신 글자로 쓴다. sandbox 안에서는 링크가 눌리지 않는다.
5. **굽기.** `node <이 폴더>/build.mjs deck.html --name <앱-이름>` → `out/`에 `<이름>.html` · `<이름>.pdf` · `<이름>-cover.jpg`(표지 한 장) · `slides/01.png …`(영상용 1920×1080) · `sandbox.png` · `report.json`.
   - 글꼴은 슬라이드에 쓴 글자만 남기고, 그림은 보이는 크기의 두 배로 다시 저장해 파일 안에 넣는다. HTML이 5MB를 넘으면 그림을 한 단계씩 줄여 다시 굽는다(`--html-max` · `--pdf-max`로 한도를 바꾼다).
   - 결과 HTML을 `<iframe sandbox="allow-scripts">` + 바깥 요청을 막는 CSP 안에서 열어 본다. 바깥 요청 · CSP 거절 · 안 뜨는 그림 · 글꼴이 하나라도 있으면 실패.
   - **실패**(바깥 요청 · 크기 초과 · 넘침 · PDF 쪽 수가 슬라이드 수와 다름)는 고쳐서 다시 굽는다. 실패가 남은 채로 넘기지 않는다.
   - **경고**(숫자 확인 · 개인정보 · 작은 글자 · 장 수 · 링크)는 하나씩 읽고, 고치거나 사용자에게 묻는다.
6. **눈으로 보기.** `out/slides/*.png`와 `sandbox.png`를 열어 본다. 한 글자만 다음 줄로 넘어간 제목, 강조가 두 군데인 장, 작아서 안 읽히는 화면을 고친다.
7. **영상(원할 때만).** 장면표(초 · 화면 · 자막)를 먼저 보여 주고 답을 받는다. 30~60초.
   - 화면 녹화는 사용자가 찍은 파일(QuickTime · 폰 화면 녹화 · OBS)을 먼저 쓴다 — 실제로 눌러 쓰는 모습이 보인다. 없으면 `node <이 폴더>/capture.mjs <주소> / --record 10`이 공개 화면을 천천히 내려 보는 녹화(`shots/home-pc.mp4` · `home-phone.mp4`)를 만든다.
   - `video.json`에 장면을 적는다(꼴은 `video.mjs` 머리 주석). 슬라이드 그림(`out/slides/NN.png`) · 녹화 · 끝 카드, 장면마다 자막.
   - `node <이 폴더>/video.mjs video.json out/intro.mp4` — 기본은 가로 1920×1080(월드컵 뷰어에 맞음). 세로(쇼츠 · 릴스)는 `--size 1080x1920`, 녹화는 폰 화면으로.
   - 첫 장면은 0초에 이미 다 보인다(미리보기가 0초 화면). 장면은 3~6초, 자막은 장면마다 두 줄 이하.
   - 목소리는 선택이다. 직접 녹음한 파일을 `--audio voice.m4a`로 넣고 장면 초를 말에 맞춘다. 맥이면 `say -v Yuna -o voice.aiff "…"`가 무료지만 기계음이다. 유료 음성 API는 쓰지 않는다.
8. **점검표 → 올리기.** `checklist.md`를 위에서부터 보고 올리는 법을 안내한다. 올리기 · 계정 일은 사용자가 한다.
   - 문서: `out/<이름>.pdf`(20MB 이하) 또는 `out/<이름>.html`(5MB 이하, 한 파일). 내용이 같으니 하나면 된다. 등록 화면의 소개 자료 칸에 올린다.
   - 영상: 사용자가 유튜브에 올리고('일부 공개'도 된다) 주소를 붙여 넣는다.

## 지킬 것

- **프로젝트에 근거가 없는 것은 쓰지 않는다.** 양식의 칸도 슬라이드의 문장도 같다. 모르는 칸은 비우고, 필수 칸이면 묻는다.
- **없는 숫자를 만들지 않는다.** 사용자 수 · 매출 · 만족도 · 줄어든 시간 · 'n배' · 시장 규모는 사용자가 잰 값과 그 출처를 줄 때만 쓴다. 숫자가 든 줄에는 `data-source="어디서 · 언제 · 어떻게 잰 값"`을 붙이고, 같은 출처를 슬라이드에도 글자로 적는다(`.src` 줄). 잰 값이 없으면 '써 본 결과' 장을 통째로 뺀다. 예상치는 예상치라고 쓴다.
- 확인 안 되는 최상급 · 보장 표현을 쓰지 않는다("최초", "유일", "완벽", "100%").
- 대결에 보이는 세 줄과 화면 한 장에서 앱 이름을 앞세우지 않는다. 이름은 로그인한 회원에게 열린다.
- 화면은 실제 앱 화면이다. 디자인 시안이나 만든 그림이면 그렇다고 적는다.
- 남의 로고 · 사진 · 음악 · 글은 쓸 권리가 있는 것만.
- 연락처는 꼭 필요한 것만. 캡처 · 녹화 속 다른 사람의 정보, 키 · 토큰 · 관리자 화면은 가린다.
- AI로 만든 사실적인 이미지 · 목소리를 넣었으면 올릴 때 매체의 AI 표시 칸을 켠다.
- 자세한 점검표는 `checklist.md`.

## 월드컵 뷰어와 맞춘 것

- 화면에서는 한 번에 한 장, 창 크기에 맞춰 줄어든다. ↑ ↓ · PageUp/PageDown · 스페이스 · 밀기 · 아래 단추로 넘긴다. 따로 열면 ← →도 된다.
- 다른 페이지 안(iframe)에 들어가면 아래 쪽 단추(n/N)를 숨긴다 — 뷰어가 쪽 번호를 따로 그린다. ← → Enter는 넘기지 않고 바깥에 알린다(`{type:"deck:key"}`) — 바깥 페이지가 쓰는 키다. 장이 바뀔 때마다 `{type:"deck:page", page, pages}`를 보내고, `{type:"deck:go", to:"next" | "prev" | 번호}`를 받으면 그 장으로 간다.
- 인쇄(PDF)에서는 한 장이 한 쪽. 저장소 · 쿠키 · 네트워크를 쓰지 않는다.

## 필요한 것

- 출품 양식 검사(`sheet.mjs`)는 Node 18 이상만 있으면 된다. 깔 것이 없다.
- 화면 캡처 · 소개 자료는 작업 폴더에서 `npm i playwright subset-font` 한 번(스크립트는 작업 폴더에 깐 패키지도 찾는다). 설치된 크롬을 먼저 쓰고, 없으면 `npx playwright install chromium`.
- 영상은 ffmpeg(`brew install ffmpeg` 등). 다른 곳에 있으면 `FFMPEG=경로`.
- 8장 · 그림 3장 예시가 M2 Pro 맥에서 굽기 약 5초, 43초 영상 약 70초.
