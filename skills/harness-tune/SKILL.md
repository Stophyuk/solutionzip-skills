# 하네스 정비

하네스는 모델 바깥에서 일을 잘하게 만드는 것 전부(지시 파일, 기억, 자동 검사, 스킬, 권한)다. 처음에 잘 짜도 프로젝트가 자라면 파일은 커지고 기억은 낡는다. 한 달에 한 번 같은 방법으로 재고, 덜어 내고, 전후를 남긴다.

## 순서

1. 범위를 정한다. 프로젝트 폴더에서 부르면 그 프로젝트, 홈에서 부르면 전역과 최근 쓴 프로젝트 전체.
2. 집계. `scripts/`를 `python3 -I`(셸 스크립트는 `bash`)로 돌린다. 결과는 임시 폴더에. 마지막 숫자는 일 수.
   - `parse_sessions.py <out>`: 세션별 길이 · 압축 횟수 · 도구 · 스킬 사용 · 오류(세션 기록은 기본 30일만 남는다. `cleanupPeriodDays`를 늘려 두면 더 길게 본다)
   - `parse_history.py <out> 30`: 입력 기록(`~/.claude/history.jsonl`)의 프로젝트별 지시 수 · 시간대 · 슬래시 명령
   - `git_stats.sh <out> 30`: 저장소별 커밋 수 · fix 비율 · 되돌림
   - `cross_metrics.py <out>`: 압축 직후 교정 표현 비율, 오류 유형
   - 사용자에게 `/insights`, `/doctor`도 권한다.
3. 점검 목록
   - CLAUDE.md: 200줄을 넘나, 진행 상황 · 날짜가 든 문장이 있나, 프로젝트 단계가 바뀌었는데 "하지 말 것 · 명령"이 옛 단계 그대로인가.
   - 메모리: `MEMORY.md` 크기(25KB를 넘으면 뒤가 잘린다), 중복 · 낡음 · 서로 충돌, 다른 폴더 메모리와 사실이 다른 것. 모든 프로젝트용 규칙이 홈 폴더 메모리에만 있으면 프로젝트 세션엔 닿지 않는다.
   - '지난 실수' 같은 교훈 칸: 같은 실수가 두 번 이상 적혔으면 테스트 · 검사 스크립트 · 훅으로 옮길 후보.
   - 이번 달 반복된 교정: 검사로 옮길 후보.
   - 훅 기록이 있으면(예: `~/.claude/hooks/log.jsonl`) 몇 번 걸렸고 몇 번 우회됐는지. 우회가 많으면 오탐을 고친다.
   - 플러그인 · 스킬 · MCP: 한 달 동안 안 쓴 것은 끄기 후보. 플러그인 스킬 목록은 세션마다 실린다.
4. 보고는 읽는 글로. 바꿀 것마다 지금 → 바꾼 뒤 → 사용자가 할 일. 지우는 대신 보관 폴더로 옮기는 안을 먼저 낸다.
5. 승인받은 것만 고친다.
6. 기록 파일(기본 `~/harness-review/하네스_성장기록.md`, 사용자가 다른 곳을 쓰면 그곳)의 맨 위에 새 항목을 더한다. 한 줄 요약, 정비 전 숫자, 전후 표, 바꾼 것, 알게 된 것, 다음 정비 때 잴 것. 지난 항목의 "다음에 잴 것"을 이번 숫자로 채운다. `build_growth.py`가 있으면 HTML과 PDF로 다시 굽는다.

## 원칙

- 예외가 없어야 하는 것(비밀값, 배포 전 검사, 민감 파일)만 훅으로 막는다. 문구 · 디자인 같은 취향은 경고까지만.
- 모델이 바뀌면 부품을 하나씩 빼 보고, 빼도 같으면 덜어 낸다.
- 숫자는 같은 스크립트, 같은 기간으로 잰다. 그래야 전후를 견줄 수 있다.
