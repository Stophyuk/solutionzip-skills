# 숏폼 스킬

장면을 HTML · CSS 애니메이션으로 짜고, 헤드리스 크롬으로 1/30초씩 넘기며 찍어 ffmpeg로 잇는다. 실시간 재생이 아니라서 컴퓨터가 느려도 프레임이 빠지지 않고, 같은 HTML은 언제 뽑아도 같은 영상이 된다.

## 순서

1. **대본 — 첫 1초가 전부.** 먼저 장면표를 사용자에게 보여 준다(초 · 화면 글 · 말).
   - 0~3초: 보는 사람이 머릿속으로 답하는 물음, 또는 결과 화면 · 숫자 하나.
   - 가운데: 한 장면에 한 가지. 장면은 2~4초.
   - 끝 2~3초: 할 일 하나(저장 · 보내기 · 링크).
   - 전체 15~45초. 처음엔 짧게.
2. **HTML 쓰기.** 이 폴더의 `template.html`을 작업 폴더로 복사해 고친다.
   - 장면 = `<section class="scene" data-start="3" data-end="6.4">`(초).
   - 움직임은 CSS 애니메이션으로. **`animation-delay`는 영상 처음부터 센 초**다(장면 기준이 아님).
   - `[data-on]`으로 애니메이션을 시작하지 않는다. 장면을 보이고 숨기는 데만 쓴다.
   - 영상 길이는 `<main data-duration="13">`, 표지로 쓸 시점은 `data-cover="1.2"`.
   - 더 복잡한 움직임이 필요하면 페이지에 `window.seek = (t) => { ... }`를 직접 정의한다(렌더러가 그걸 부른다).
3. **목소리(있으면).** 원하는 TTS나 녹음으로 `voice.mp3`를 만들고, 장면 시각을 말에 맞춘다. 자막은 화면 글로 넣는다.
4. **찍기.** `node <이 폴더>/render.mjs short.html out.mp4 [--audio voice.mp3]` → `out.mp4` + 표지 `out.jpg`.
   - 안전 영역(x 80–960 · y 260–1540) 밖 글자는 경고로 알려 준다. 매체 버튼 · 캡션에 가리므로 고친다.
5. **보기.** 영상을 처음부터 끝까지 본다. 0초 화면(피드 미리보기)과 표지가 읽히는지 본다.

## 지킬 것

- 같은 틀에 글만 바꾼 영상을 대량으로 찍어 내지 않는다(유튜브는 반복 · 대량 생산 콘텐츠를 단속한다). 편마다 장면 구성을 바꾼다.
- 확인 안 된 숫자 · 최상급 · 보장 표현을 쓰지 않는다. '1분', '무료'를 말하면 잰 값 · 조건을 화면에 같이.
- AI 목소리 · 사실적인 AI 영상이면 올릴 때 AI 표시 칸을 켠다.
- 남의 음악 · 영상은 쓸 권리가 있는 것만.
- 자세한 점검표는 `checklist.md`.

## 필요한 것

- Node 18 이상 + `npm i playwright`(설치된 크롬을 먼저 씀) + ffmpeg(`brew install ffmpeg` 등).
- 13초 · 30fps 예시가 M2 맥북에서 약 45초 걸린다.
