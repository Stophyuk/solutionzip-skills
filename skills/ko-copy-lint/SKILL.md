# 한국어 카피 검사 스킬

사람이 읽는 글만 골라 검사한다. 코드의 문자열과 JSX 글, HTML의 태그 밖 글, 마크다운 본문이 대상이고 주석은 보지 않는다. 한글이 든 조각만 본다.

## 순서

1. **범위 정하기.** 무엇을 볼지 사용자에게 한 줄로 확인한다(예: `app/`의 화면 문구 + `content/`의 글). 법률 문서(약관 · 처리방침)는 기본으로 뺀다.
2. **프로젝트 규칙 확인.** 저장소 맨 위에 `copy-lint.json`이 있으면 읽는다. 없고 사용자가 금지어를 말하면 만들어 준다.
   ```json
   { "banned": ["옛 서비스 이름"], "allow": ["다양한"], "allowDash": false, "ignore": ["legal/"] }
   ```
   - `banned`: 나가면 안 되는 말(옛 이름, 쓰지 않기로 한 호칭). 걸리면 실패.
   - `allow`: 이 프로젝트에선 괜찮다고 정한 말. 기본 목록에서 뺀다.
3. **돌리기.** `node <이 폴더>/lint.mjs <경로…>`. 결과는 `✗`(실패) · `△`(경고) 줄과 개수.
4. **읽고 판단하기.** 기계가 잡은 것을 다 고치지 않는다. 줄마다 그 문장을 읽고 나눈다.
   - 사실이고 근거가 있다(측정한 숫자, 공식 순위 출처가 있다) → 그대로 두고 근거를 옆에 적자고 제안한다.
   - 근거가 없다 → 고친다. 무엇이 실제로 바뀌는지, 누가 무엇을 하는지로 바꾼다.
   - 상투어 → 그 자리에 들어갈 구체적인 말(무엇을, 몇 번, 어디서)로 바꾼다.
5. **고칠 문장 제안.** 원문 → 바꾼 문장 꼴의 표로 보여 주고, 사용자가 고르면 고친다. 자동으로 한꺼번에 바꾸지 않는다.
6. **다시 돌려** 실패 0을 확인한다.

## 지킬 것

- "하지 않습니다"처럼 하지 않는 일을 말하는 문장의 '보장' · '1위'는 걸리지 않는다. 한계를 밝히는 문장은 좋은 문장이다.
- 업계 용어(플랫폼 · 대시보드 · API)는 맞는 자리라면 고치지 않는다. 문제는 낱말이 아니라 확인할 수 없는 주장이다.
- 바꾼 문장에 새 숫자를 지어 넣지 않는다. 숫자가 필요하면 사용자에게 묻는다.
- 자세한 기준과 바꾼 예는 `rules.md`.

## 필요한 것

- Node 18 이상. 의존성 없음.
- 배포 전 검사에 넣으려면 `--strict`(경고도 실패로) 또는 기본(실패만 막음)을 package.json scripts에 건다.
