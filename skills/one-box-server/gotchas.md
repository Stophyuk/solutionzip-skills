# 서버 한 대 — 겪은 함정

앱 여러 개를 한 서버에서 운영하며 실제로 걸렸거나, 걸린 뒤 막아 둔 것들이다. 한 줄에 하나, 줄표 뒤가 이유다. 템플릿 주석에도 같은 말이 그 자리에 있다.

## 크론 · 셸

- **크론 시각은 호스트 시간대로 적는다** — Ubuntu의 cron은 `CRON_TZ`를 무시한다. `CRON_TZ=UTC`를 적은 파일이 아홉 시간 어긋나 돌았고, 실패는 아무도 안 보는 로그 파일에만 쌓였다.
- **cron.d 줄에 `%`를 쓰지 않는다** — cron이 `%`를 줄바꿈으로 바꾼다. `date +%F` 같은 것은 스크립트 안으로.
- **파이프 뒤에 `grep -q`를 쓰지 않는다(`pipefail`일 때)** — 첫 줄에서 grep이 끝나면 앞 명령이 SIGPIPE로 죽고, 찾았는데도 실패로 읽힌다. 이것 때문에 "크론이 성공하지 않음" 거짓 메일이 매시간 왔다. `grep … >/dev/null`로 끝까지 읽힌다.
- **`ssh host bash -s <<EOF`로 보낸 스크립트 안에서 stdin을 읽는 명령에는 `</dev/null`** — 그 명령이 남은 스크립트를 stdin으로 읽어 버려 뒷부분이 실행되지 않는다. `docker compose exec`, `psql`, `while read` 안의 명령이 그렇다.
- **root는 다른 사용자가 `/tmp`에 만든 잠금 파일을 못 연다** — `fs.protected_regular=2`. 배포 잠금(`/tmp/deploy.lock`)을 함께 쓰는 크론 줄은 배포하는 사용자로 돌리거나, 잠금을 `/tmp` 밖에 둔다.
- **크론 경로는 호스트에서만 부를 수 있게 한다** — 엣지에서 `/api/cron/*`를 404로 막고 호스트가 `127.0.0.1:<port>`로 부른다. 앱이 죽어 있으면 앱은 자기 크론 실패를 알릴 수 없으니, 부르는 쪽(cron-call.sh)이 2xx가 아니면(000 포함) 메일을 보낸다.
- **경보는 키별 6시간에 한 통, 그사이 쌓인 개수는 다음 통에** — 매시간 도는 검사가 같은 이유로 실패하면 하루 24통이 와서 결국 안 읽게 된다.

## env · compose

- **compose의 `--env-file`은 값 속 `$`를 해석한다** — `pbkdf2$210000$salt$hash` 같은 값이 `$` 뒤로 잘린다. 합칠 때 `$`를 `$$`로 바꾸고, 서비스에는 `environment:`로만 넘긴다(`env_file:`은 `$$`를 그대로 넘긴다).
- **원격 `.env.pushed`는 통째로 바뀐다** — 로컬 파일에 빠진 이름은 서버에서도 사라진다. 꼭 있어야 하는 이름을 먼저 검사하고 하나라도 없으면 보내지 않는다.
- **키는 첫 `db` 기동 전에 만든다** — 이미지의 init 스크립트(roles.sql · jwt.sql)는 빈 볼륨의 첫 기동에서만 비밀번호와 JWT 비밀을 읽는다.
- **`.env.generated`를 다시 만들지 않는다** — 새 JWT 비밀은 모든 세션을 끊고 빌드에 박힌 anon 키를 무효로 만든다. 해시 · 서명 키가 바뀌면 저장된 해시가 안 맞고 이미 보낸 메일의 링크가 안 열린다. 매일 밤 버킷에 올리고, 새 서버에선 되살린다.
- **비밀번호는 16진수로 만든다** — 연결 URL(`postgres://user:pw@db`) 안에서 이스케이프가 필요 없다.
- **`NEXT_PUBLIC_*`는 빌드할 때 박힌다** — 빌드 인자로 넘긴다. 비밀은 빌드 인자로 넘기지 않는다(이미지 기록에 남는다).
- **Server Actions 키를 고정한다** — 빌드마다 새 키가 생기면 배포 전에 열어 둔 폼이 "Failed to find Server Action"으로 실패한다. BuildKit secret으로 넘긴다.
- **`.dockerignore`에 `.env*`** — 없으면 `COPY . .`가 로컬 비밀을 이미지 층에 굽는다.
- **`up --wait`는 헬스체크가 있어야 기다린다** — 없으면 "running"에서 바로 돌아와, 안 뜬 판을 성공으로 본다.

## DB (Supabase 이미지)

- **이미지 init은 `auth.*` 함수를 `postgres` 소유로 두고 storage 스키마를 비워 둔다** — GoTrue · storage-api가 자기 것을 마이그레이션하려면 소유자를 넘겨야 한다(`db-bootstrap.sql`).
- **storage 관리 역할을 `anon` · `authenticated` · `service_role`에 넣는다** — storage-api는 요청마다 그 역할로 바꾸는데, 멤버가 아니면 업로드가 전부 거절된다.
- **이미지에 없는 역할을 roles.sql에 적지 않는다** — psql이 첫 오류에서 파일을 멈춰 뒤의 역할들이 비밀번호 없이 남는다.
- **마이그레이션 뒤 `notify pgrst, 'reload schema'`** — PostgREST는 스키마를 캐시한다. 안 하면 새 표 · 열이 재시작 전까지 404다.
- **이미지는 되돌려도 DB는 안 돌아간다** — 그래서 마이그레이션은 더하기만 한다(앞 판 이미지가 새 스키마에서도 돈다). 적용 전에 덤프를 뜬다.
- **migrate.sh는 Supabase CLI와 같은 표를 쓴다** — SSH 터널로 `supabase db push --db-url`을 써도 기록이 섞이지 않는다.

## Caddy

- **Caddyfile을 컨테이너 재시작으로 적용하지 않는다** — 파일이 틀리면 모든 호스트가 같이 내려간다. `caddy reload`는 틀린 파일을 거절하고 옛 설정으로 계속 돈다.
- **Caddyfile은 제자리에 쓴다** — 한 파일 바인드 마운트는 inode를 따라간다. cp가 이름 바꾸기로 덮거나 git checkout이 새 파일을 만들면 컨테이너는 옛 파일을 계속 읽는다.
- **`roll_keep_for`는 굴려진 파일만 지운다** — 트래픽이 적으면 지금 쓰는 파일에 몇 달 치가 남는다. 보존 약속(예: 30일)을 지키려면 `ts`로 줄을 걸러 낸다(trim-logs.sh).
- **storage-api는 CORS를 답하지 않는다** — 호스팅 Supabase는 앞에 게이트웨이가 있다. 다른 출처에서 storage를 부르면 storage 경로에만 CORS를 붙인다. PostgREST · GoTrue에는 붙이지 않는다(두 번 붙으면 브라우저가 거절한다).
- **스트리밍 응답이 있는 호스트는 `encode`를 빼고 `flush_interval -1`** — 안 그러면 Caddy가 모았다가 한꺼번에 보낸다.
- **같은 서버의 컨테이너가 공개 API 주소를 부를 때는 엣지 네트워크 별칭으로** — Caddy 컨테이너에 그 호스트 이름을 별칭으로 붙이면 진짜 인증서로, 헤어핀 NAT 없이 닿는다.
- **처음 리허설은 스테이징 CA로** — 발급 한도에 걸리면 한동안 인증서를 못 받는다.

## 서버 · 디스크

- **스왑을 잡는다** — 서버에서 Next를 빌드하면 1.5~2.5GB까지 올랐다. 스왑이 없으면 OOM 킬러가 DB를 고를 수 있다.
- **스왑 사용량은 `SwapTotal − SwapFree − SwapCached`** — SwapCached는 이미 램에 돌아온 사본이다. 빼지 않았을 때 1,223MB로 보였는데 실제로 디스크에 나가 있던 것은 449MB였다.
- **빌드 캐시를 매일 밤 지운다** — 빌드가 많은 날 캐시만으로 디스크가 80%까지 찼다. 배포 잠금 안에서 지워 빌드를 반으로 자르지 않는다.
- **컨테이너 로그 크기를 데몬에서 한 번에 막는다** — `daemon.json`의 `max-size` · `max-file`. 도커 기본 json-file 로그는 한도 없이 자란다.
- **journald는 하루마다 파일을 굴린다(`MaxFileSec=1day`)** — `MaxRetentionSec`은 파일 단위로 지워서, 안 굴리면 보존 기한의 두 배 가까이 남는다.
- **자동 재부팅을 끈다** — 보안 업데이트는 자동, 재부팅은 사람이 달마다 정한 시간에.

## 백업 · 복구

- **실패한 밤이 조용히 지나가지 않게 두 겹** — 스크립트의 ERR 트랩이 메일을 보내고, 매시간 검사가 오늘의 "backup ok" 줄이 없으면 또 보낸다.
- **보존은 스크립트가 지운다(버킷 수명 규칙 없이)** — 지울 이름은 날짜 꼴만 통과시킨다. 빈 이름이 `daily/` 전체로 넓어지지 않게.
- **복구 연습 컨테이너는 `--network none`** — 되살린 데이터가 어디에도 말을 걸 수 없게.
- **연습은 행 수를 운영과 견준다** — 덤프 뒤에 생긴 행만큼 운영이 앞서 있는 것은 정상, 그 밖의 차이는 설명돼야 통과.
- **덤프 · 백업 파일은 `umask 077`** — 모든 사용자의 행이 들어 있다.

## auth(GoTrue)를 더한다면

- **GoTrue는 루프백 `redirect_to`를 허용 목록과 상관없이 통과시켰고, `redirect_to` 헤더와 Referer도 돌아갈 주소로 읽었다(2.196에서 확인)** — 폰의 다른 앱이 로그인 토큰을 받을 수 있다. 엣지에서 두 헤더를 지우고 실제 돌아갈 주소만 통과시킨다.
- **authorize에 `code_challenge`가 없으면 막는다** — 없으면 GoTrue가 토큰을 URL 조각에 담아 준다(implicit). PKCE만 받는다.
- **앱이 안 쓰는 auth 경로는 인터넷에서 닫는다** — 관리 API · 초대 · SSO 등. 같은 서버 컨테이너가 쓰는 관리 경로는 사설 대역에만 연다.
- **메일 한도 로그는 시간당 한도만 센다** — 같은 주소의 짧은 재요청("request this after N seconds")도 같은 오류 코드로 남는다.
