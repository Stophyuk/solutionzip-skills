# 전 페이지 캡처 스킬

페이지마다 한 화면씩 잘라 찍는다. 긴 페이지를 한 장으로 찍으면 폰 폭에선 글자가 안 보이기 때문이다. 폰 화면은 두 장씩 나란히 붙인 그림도 만든다. 모든 그림은 `index.html` 한 장에서 훑는다.

## 순서

1. **주소와 범위 확인.** 사용자에게 주소를 받고, 어느 페이지를 찍을지 한 줄로 보여 준다.
   - 기본은 `/sitemap.xml`의 페이지, 없으면 첫 페이지에 걸린 링크(같은 사이트만). 30개까지.
   - 로그인이 필요한 페이지 · 결제 · 제출 버튼은 찍지 않는다. 운영 사이트라면 폼을 보내지 않는다.
2. **고정 막대 빼기.** 화면 아래 고정 버튼 · 쿠키 띠 · 채팅 버튼은 통째로 찍으면 페이지 중간에 그려진다. 선택자를 `--hide`로 뺀다.
3. **찍기.** `node <이 폴더>/shots.mjs <주소> [--hide ".cookie-bar"] [--out shots]`
   - 특정 페이지만: 경로를 뒤에 늘어놓는다(`/ /about /faq`).
   - 메뉴를 연 상태 같은 장면이 필요하면 `pages.json`에 `click` 순서를 적어 `--config`로 준다(꼴은 `shots.mjs` 머리 주석).
4. **결과 읽기.** 끝에 실패 줄(✗)과 개수가 나온다. `report.json`에 페이지 · 폭마다 실패 · 경고가 있다.
   - **가로로 밀림**(폰): 가장 튀어나온 요소의 태그와 클래스가 같이 찍힌다. 거기서부터 고친다.
   - **HTTP 404 · 열리지 않음**: 사이트맵이나 링크가 죽은 페이지를 가리킨다.
   - 경고(그림 · 스크립트 오류 · 문자셋)는 읽고 판단한다.
5. **눈으로 보기.** `index.html`을 열고(또는 폰 두 장 그림을 직접 열어) 기계가 못 잡는 것을 본다 — 큰 제목이 이상하게 끊기는 곳, 버튼이 겹치는 곳, 너무 작은 글자. 찾은 것을 페이지 · 폭 · 위치로 적어 보고한다.
6. 고친 뒤 같은 명령으로 다시 찍어 전후를 견준다.

## 지킬 것

- 남의 사이트를 찍을 때는 그 사이트에 부담이 가지 않게 페이지 수를 줄인다(`--max`). 찍은 그림을 공개하려면 권리를 확인한다.
- 운영 중인 사이트의 방문 통계에 잡힐 수 있다. 통계를 깨끗이 두려면 개발 서버 주소로 찍는다.
- 보고에는 고칠 곳만. 잘 된 페이지를 하나하나 칭찬하지 않는다.

## 필요한 것

- Node 18 이상, 작업 폴더에서 `npm i playwright` 한 번. 설치된 크롬을 먼저 쓰고, 없으면 `npx playwright install chromium`.
