# 1인 개발 틀

혼자 클로드 코드로 제품을 만들 때 세션마다 되풀이되는 세 가지를 파일로 막는다. 왜 이렇게 하는지는 `why.md`.

1. **상태는 문서에 적지 않고 파일에서 계산한다.** 세션 시작 훅이 git과 대장 셋을 읽어 요약을 매번 새로 만든다.
2. **실수는 그 일을 맡은 파일의 '지난 실수' 절에 적는다.** `/record`가 먼저 묻는다. 다음 세션에 그 파일이 열리면 같이 읽힌다.
3. **푸시 전 게이트.** `git push` 직전에 빠른 검사를 돌려 첫 실패에서 막는다.

## 깔리는 것

| 파일 | 하는 일 |
|---|---|
| `.claude/hooks/session-start.mjs` | 세션 머리 요약. 경로 · 절 이름은 맨 위 `CONFIG` 하나에. 파일이 없으면 그 줄은 건너뛴다 |
| `.claude/hooks/pre-push.mjs` | 푸시 게이트. package.json scripts에서 `preflight` · `typecheck` · `lint` 중 있는 것만 돌린다 |
| `.claude/skills/record/SKILL.md` | `/record <제목>` — 실수 · 결정 · 마일스톤 · 변경 기록을 물어 갱신하고 docs 커밋 |
| `.claude/rules/example.md` | 경로별 규칙 본보기(`paths:` frontmatter) |
| `CLAUDE.md` | `CLAUDE.md.example`에서. 프로젝트에 CLAUDE.md가 없을 때만 |
| `docs/milestones.md` · `decisions.md` · `changelog.md` | 빈 대장 셋 |
| `.claude/settings.json` | `settings.hooks.json`의 훅 셋을 기존 설정에 합친다 |

## 순서 — "1인 개발 틀 깔아줘"

1. **훑기.** 프로젝트를 먼저 본다 — CLAUDE.md · README에 상태 문장("어디까지 됐다")이 있는지, 이미 대장 구실을 하는 문서(TODO · ROADMAP · 결정 기록)가 있는지, package.json scripts, `.claude/settings.json`의 기존 훅.
2. **계획 보여 주기.** `node <이 폴더>/install.mjs <프로젝트>` — 아무것도 쓰지 않고 계획만 낸다. 이것을 정리해 사용자에게 보여 준다.
   - 새로 깔 파일 / 이미 있어 그대로 둘 파일(`같음` · `다름` · CLAUDE.md의 빠진 절)
   - settings.json에 보탤 훅
   - 푸시 게이트가 돌릴 명령. **`검사 없음`이면 그렇게 말하고** 어떤 검사를 붙일지 묻는다(scripts에 추가하거나 `pre-push.mjs`의 `EXTRA`)
   - 이미 있는 문서를 대장으로 쓸지(그러면 경로 · 절 이름을 `CONFIG`에 맞춘다), 새 대장을 깔지 묻는다.
3. **확인 받으면 깔기.** `node <이 폴더>/install.mjs <프로젝트> --apply`.
   - 있는 파일은 덮지 않는다. `다름`으로 나온 파일은 출력의 `diff -u` 명령으로 차이를 보여 주고 어떻게 할지 묻는다.
   - settings.json이 JSON으로 읽히지 않으면 스크립트가 손대지 않는다. `settings.hooks.json`을 보고 손으로 합친다 — 기존 훅 · 권한은 지우지 않는다.
4. **맞추기.**
   - 대장 경로나 절 이름이 다르면 `session-start.mjs`의 `CONFIG`만 고친다.
   - CLAUDE.md를 새로 깔았으면 `<…>` 빈칸을 사용자와 채운다. 원래 있었으면 빠진 절만 보태자고 제안한다. 상태 문장은 대장으로 옮기고 그 자리엔 대장을 가리키는 한 줄만 남긴다.
   - 규칙 본보기는 첫 규칙 하나로 바꾸거나 지운다(이름 · `paths:` · 내용).
   - 프로젝트에 이미 있던 할 일 · 결정이 있으면 대장에 옮겨 적을지 묻는다. 옮길 때 상태 칸 첫 글자 약속(아래)을 지킨다.
5. **확인.** 둘 다 돌려 출력을 사용자에게 보여 준다.
   - `echo '{}' | node .claude/hooks/session-start.mjs` — 요약이 나오고 종료 코드 0인지.
   - `node .claude/hooks/pre-push.mjs --dry-run` — 돌릴 검사 목록.
   - 훅은 새 세션부터 돈다. 이미 열린 세션이면 `/hooks`에서 확인하거나 다시 연다.
6. **커밋은 사용자가 정한다.** 제안만 한다 — 예: `chore: 1인 개발 틀(세션 요약 · 푸시 게이트 · /record)`.

## 이 틀로 일하는 법

- **상태의 근거는 세션 머리 요약뿐이다.** CLAUDE.md · README · 메모리의 상태 문장은 사본이다. "어디까지 됐나"는 `node .claude/hooks/session-start.mjs --list`로 답한다.
- **열린 결정은 정하지 않는다.** `docs/decisions.md` '열린 결정'에 있는 것에 부딪히면 그 번호로 묻는다. 정해지면 `/record`가 '정한 것'으로 옮긴다.
- **한 덩어리가 끝나면 사용자가 `/record <제목>`.** 실수부터 묻고, 대장을 고치고, `docs: 기록 — <제목>` 커밋을 만든다. 요약의 '기록 뒤 커밋 N개'가 쌓이면 부를 때다.
- **실수는 맡은 파일에.** 스킬로 한 일은 그 스킬의 `## 지난 실수`, 경로에 묶인 일은 `.claude/rules/<이름>.md`의 `## 지난 실수`. 규칙 파일은 `paths:`에 맞는 파일을 열 때만 뜬다.
- **푸시가 막히면 고쳐서 다시 푸시한다.** 검사를 끄거나 우회하지 않는다. 클로드 코드 쪽 훅이라 `git push --no-verify`로는 넘어가지 않는다.

## 지킬 것

- 사용자 파일을 덮지 않는다. settings.json은 합치기만 한다.
- 대장 표의 상태 칸은 **첫 글자**가 약속이다: ✅ 끝 · ◐ 하는 중 · ⏳ 기다림 · ☐ 아직. 세부는 뒤에. 다른 글자로 시작하면 요약에 `?`로 뜬다.
- 결정 번호는 두 표를 통틀어 가장 큰 번호 + 1. 요약이 '다음 번호'를 알려 준다. 개수 · 번호를 다른 문서에 옮겨 적지 않는다.
- 게이트에는 빠른 검사만 둔다(합계 280초 안). 빌드 · 느린 시험은 CI로.
- 세션 시작 훅은 늘 0으로 끝난다. 계산 못 한 줄은 빠질 뿐 세션을 막지 않는다.

## 필요한 것

- Node 18 이상, git. 의존성 없음.
- 푸시 게이트는 package.json scripts(`preflight` · `typecheck` · `lint`)나 `pre-push.mjs`의 `EXTRA`. 패키지 매니저는 `packageManager` 필드 → lockfile → npm 순으로 고른다.
- settings의 `if` 필터(`Bash(git push *)`)가 훅을 push 명령일 때만 띄운다. 스크립트도 받은 명령을 다시 보고 push가 아니면 바로 통과시킨다(두 번째 그물).
